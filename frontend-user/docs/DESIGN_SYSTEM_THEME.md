# 设计系统 · 可切换配色方案（深 / 浅）

驾驶舱现提供两套可切换的配色方案，定义与口径以 `frontend-user/css/variables.css` 为唯一事实源（Single Source of Truth）。

| 主题 | 挂载方式 | 定位 |
| --- | --- | --- |
| 深色霓虹 `dark` | `<html data-theme="dark">` | 品牌默认，Cyberpunk/Vaporwave，取值与历史版本完全一致 |
| 浅色霓虹 `light` | `<html data-theme="light">` | 日间/投屏可读版本，同色相加深，通过 WCAG 2.1 AA |

切换入口：左上角悬浮按钮（☀️ / 🌙）。选择写入 `localStorage`（键：`kabrita-dashboard-theme`），刷新与重开页面后保持；首次访问跟随系统 `prefers-color-scheme`，无系统偏好时默认深色。

## 一、配色口径（Token Contract）

1. 页面只允许两类颜色来源：
   - 语义令牌：`--text-*`、`--status-*`、`--neon-*`、`--surface-*`、`--chart-*` 等；
   - RGB 通道令牌：`rgba(var(--rgb-purple), 0.2)` 形式，用于透明度合成。
2. 两套主题令牌名称完全一致，仅取值不同。组件 CSS、图表 JS、数据文件中**禁止写死十六进制 / rgba 色值**，新增颜色必须在变量层登记。
3. 主色走向两套保持一致（紫→粉→青→绿），浅色只降明度、换表面色，因此霓虹观感与布局不变。
4. 状态色只有四种语义，不允许新增第五种：
   - `--status-success` 成功 / 改进目标（绿）
   - `--status-error` 危险 / 当前位置（红）
   - `--status-warning` 警告（琥珀）
   - `--status-info` 信息（蓝/紫）
   矩阵「当前位置 / 改进目标」、Toast、侧栏断层卡、KPI 全部引用同一组状态令牌。
5. 图表配色（漏斗五级、雷达两条线、提示框、坐标轴、图例）使用 `--chart-*` 令牌；ECharts 在主题切换时以 `setOption(option, { notMerge: true })` 全量重绘，避免合并残留旧色。

## 二、判定标准（Conformance）

- 标准：**WCAG 2.1 AA**。
- 对比度公式：`(L1 + 0.05) / (L2 + 0.05)`，L 为 sRGB 相对亮度。
- 深色主题为品牌既有基线，装饰性辉光色不承担正文阅读；任何文字必须使用 `--text-*` 或状态色，不允许直接使用装饰霓虹色。
- 浅色主题为强制达标方案：所有文字色、状态色、带字标签、图表图形按下表阈值验收，不达标不得合入。

## 三、可读阈值（Readability Thresholds）

| 用途 | 阈值（对底色） |
| --- | --- |
| 正文 / 小号文字（< 18px，或 < 14px 加粗） | **≥ 4.5:1** |
| 大号文字（≥ 18px，或 ≥ 14px 加粗） | ≥ 3:1 |
| 非文字 UI（图标、边框、图形、图表线条/填充） | ≥ 3:1 |
| 彩色按钮 / 状态标签上的白字 | ≥ 4.5:1 |

浅色主题实测（底色 `#eceef6` / 卡片 `rgba(255,255,255,.72)`）：

| 令牌 | 色值 | 对比度（约） | 结论 |
| --- | --- | --- | --- |
| `--text-primary` | `#1b1d2c` | 15.6:1 | ✓ 正文 |
| `--text-secondary` | `#4b5264` | 6.4:1 | ✓ 正文 |
| `--text-muted` | `#5b6270` | 5.2:1 | ✓ 正文 |
| `--status-error` | `#b91c1c` | 5.6:1 | ✓ 状态/正文 |
| `--status-success` | `#047857` | 4.7:1 | ✓ 状态/正文 |
| `--status-warning` | `#92400e` | 6.1:1 | ✓ 状态/正文 |
| `--status-info` | `#1d4ed8` | 5.7:1 | ✓ 状态/正文 |
| 紫 `--neon-purple` | `#7c3aed` | 4.9:1 | ✓ |
| 粉 `--neon-pink` | `#be185d` | 5.2:1 | ✓ |
| 青 `--neon-cyan` | `#0e7490` | 5.4:1 | ✓ |

漏斗各级填充取 700 档（紫 `#7e22ce` / 粉 `#be185d` / 红 `#dc2626`、`#b91c1c`），白字标签均 ≥ 4.5:1。

## 四、切换时的联动范围（不得有旧色残留区块）

主题切换通过修改 `<html data-theme>` 一次生效，下列区域全部联动：

1. **文字与表面**：正文/次要/弱化文字、玻璃卡片、侧栏、Toast、滚动条、选中文本、按钮；
2. **状态色**：矩阵 `[当前位置]` / `[改进目标]` 单元格与标签、侧栏位置卡/断层卡、Toast 四种类型、统计趋势、KPI 数字、评分条；
3. **图表**：AARRR 漏斗（五级填充/边框/辉光/标签/提示框）、雷达图（现状/标杆线条与面积、坐标轴、分割面、图例、提示框）整图重绘；
4. **矩阵表格**：表头渐变、维度列、行悬停、单元格边框、SOP 箭头、国际/国内工具标签；
5. **氛围层**：径向辉光背景、网格覆盖层、浮动粒子（按新色板重建）；
6. **浏览器外观**：`<meta name="theme-color">` 同步更新。

## 五、扩展新颜色 / 新组件的检查清单

1. 颜色是否写进了两套主题（只写一套会导致另一套回退到继承值）？
2. 是否使用语义令牌或 `--rgb-*` 通道，而不是硬编码？
3. 浅色主题下正文对比是否 ≥ 4.5:1、UI 图形是否 ≥ 3:1？
4. 若用在白字按钮/标签上，底色对白字是否 ≥ 4.5:1？
5. 图表/Canvas 色是否走了 `--chart-*` 并支持重绘（订阅 `themeManager.onChange`）？
6. 深/浅切换后该区块是否无旧色、布局无位移？
